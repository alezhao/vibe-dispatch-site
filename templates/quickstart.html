快速开始

从安装、启动演示服务，到派发任务、查看结果与人工复核，走一遍 vibe-dispatch 的使用流程。

  1. 安装开发依赖

    准备 Python 3.10+，在 vibe-dispatch 源码目录执行：

    pip install -e ".[dev]"

  2. 启动演示服务

    在终端 1 启动常驻服务。演示模式使用假 provider 和预置任务，不碰云资源，也不产生费用。

    vibe serve --demo

    后续提交与合并在 demo 中只作演练。真实派发前，先结束 demo，配置好对应后端的凭据与运行环境，再用 vibe serve（默认 ACA）或 vibe serve --backend local-docker 启动服务。

  3. 提交任务与验收命令

    另开终端 2，以文档中的仓库和新分支为例提交任务。-a 必填：是否完成由验收命令的退出码决定，退出码 0 即通过，而不是由 agent 自述决定。

    vibe submit "为任务列表接口增加分页" \
  -r alezhao/vibe-dispatch -b feat/pagination \
  --setup "uv sync --extra dev" \
  -a "uv run python -m pytest -q"

    默认提交后立即派发；记下返回的任务 ID。准备命令与验收命令配套使用，--setup 的必要性见下方说明。

  4. 查看结果，复核后合并

    列出任务，再查看详情与 diff。将示例中的 1dac 替换为实际任务 ID 或可识别前缀。

    vibe ls
vibe show 1dac -d
vibe merge 1dac

    不要直接连续执行到合并：先等待沙箱与本机的双跑验收通过、任务进入 awaiting-review，再人工查看 diff。真实派发模式下，确认产出符合预期后执行 vibe merge，在 GitHub 开 PR 并合并已验收的提交到基线。

本例中，为什么 --setup 必填？

沙箱里只有裸 python3，没有 pip、没有 pytest。运行本例这样的测试类验收，不先准备依赖，验收命令会以 command not found 告终；这个非零退出码看上去和测试失败一样，并不意味着测试真正运行过。

因此，本例必须通过 --setup 准备验收环境。这是运行测试的环境要求，不是所有 vibe submit 都强制要求此参数。按原文建议用 uv sync --extra dev 建立项目虚拟环境，再用 uv run python -m pytest -q 验收。

准备命令在沙箱执行，本机未指定 --local-setup 时也沿用 --setup。避免用 uv pip install --system 写入系统目录：沙箱中的非特权用户会遇到权限错误。
