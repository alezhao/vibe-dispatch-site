vibe-dispatch

多任务分派的 vibe coding 开发平台

本机是 dev lead：把任务派到互不可见的隔离沙箱，由 agent 独立编码、自测并推回 GitHub；本机负责复跑验收、复核，然后合并或打回。本机不跑 agent，合并由人决定。

快速开始 在 GitHub 查看源码

从派发到复核

双跑验收

沙箱内自测通过后，本机在独立的临时 clone 中检出同一个 commit_sha，复跑同一条验收命令。两跑都过才进入待复核，agent 自己说完成不作数。

自动修复回路

沙箱内自测没过，测试输出作为反馈交回 agent，在同一棵工作树上继续修；修复轮用完则带着累计反馈整链重跑。修复轮数与尝试次数都有预算，新沙箱也能读到失败历史。

本机 worktree 模式

指定 --local-repo，为每个任务创建独立的 Git worktree 与新分支，通过 GitHub 交给沙箱，再回收到对应 worktree。输入是本机基线已提交的版本，原目录未提交、未跟踪的文件不会被打包或修改。

任务状态一览

queued
任务已登记，等待派发。
running
任务正在沙箱中执行。
self-tested
沙箱内自测通过，等待本机复跑验收。
awaiting-review
双跑验收通过，等待 dev lead 复核、合并或打回。
merged
复核通过，已在 GitHub 上通过 PR 合并进基线。
failed
机器判定不通过；不是终态，可人工重试。
rejected
人判定产出不合格，填写理由后打回；测试全绿也可能被打回。
cancelled
用户主动叫停任务，而不是任务运行失败。

merged、rejected、cancelled 是终态，后台迟到的更新不能改写它们。
