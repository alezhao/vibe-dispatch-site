CLI 参考

常用子命令速查。具体参数以 vibe <子命令> --help 为准；首次使用可先按 快速开始 演练。

十二个子命令：从环境检查到任务复核
命令 说明
vibe doctor 检查宿主工具、缓存与认证等环境条件。--repo owner/name 加查仓库可达性；--sandbox 会真实创建沙箱、执行命令再销毁。
vibe serve 启动常驻服务，任务执行留在服务端。--demo 使用假 provider 和预置任务；真实后端默认为 azure-aca-sandbox，也可用 --backend local-docker。
vibe submit 提交任务描述，用 -r 指定仓库、-b 指定新分支，必填的 -a 指定验收命令。--setup 准备验收环境，测试类验收需先安装依赖；本机可用 --local-setup 覆盖准备命令。默认立即派发，--no-start 只登记任务。
vibe ls 列出任务及状态。-w 持续刷新，-s <状态> 按状态筛选。
vibe show 按任务 ID 或前缀查看详情、双跑验收结论与 SHA。-d（--diff）查看固定验收 SHA 的三点 diff，供人工复核。
vibe logs 查看任务详细日志全文，包括阶段计时、agent 动作、验收与失败输出。-n 50 查看末尾 50 行，-f 跟随日志并在任务停下后自动退出。
vibe run 启动排队任务，配合 vibe submit --no-start 使用；重跑失败任务应使用 vibe retry。
vibe retry 重跑 failed 或 rejected 的任务，沿用原任务 ID 与描述，重置自动修复预算。可用 -m 补充反馈，旧失败原因与输出也会交给 agent。
vibe cancel 用户主动叫停任务，释放沙箱并停止计费。取消理由可选，用 -m 提供。
vibe merge 人工复核通过后，在 GitHub 为任务分支开 PR 并合并到基线，只合并已经验收的提交。本机 worktree 模式下还会尝试快进本机基线；合并失败会保留待复核产物，可修复原因后再次执行。
vibe reject 人工判定产出不合格并打回，即使测试全绿也可拒绝。拒绝理由必填，使用 -m <理由> 记录，作为后续反馈。
vibe resume 基础设施连续失败触发熔断后，先修复基础设施，再恢复排队任务派发；不是恢复单个已取消的任务。

任务状态、双跑验收与自动修复的关系，见 工作流。
